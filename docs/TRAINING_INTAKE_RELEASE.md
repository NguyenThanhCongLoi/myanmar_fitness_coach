# Complete intake and separate training collections — 2026-11-13

The former five-question flow omitted the body baseline, collapsed every health answer into one flag and applied the Home-video filter to Gym plans. The replacement saves the user's actual answers and uses a single deterministic planning pipeline. It does not invent an AI or clinical assessment.

## Intake and data use

One question per screen: age; height; weight; sex; goal; experience; everyday activity; Home/Gym; days; session time; health screening; protected areas; illustrated focus; current waist; desired waist; current glutes; desired glutes; editable review. Professional clearance is an additional conditional screen when needed. No required numeric typing: age uses a vertical wheel; height and weight use horizontal rulers (1 cm / 0.5 kg increments). Native touch scrolling, scroll snap and keyboard controls share the same value. Each measurement requires explicit confirmation; opening a picker never saves its suggested default. Required baseline: self-reported age 18–90, height 120–230 cm, weight 30–250 kg, and an explicit sex choice (including “prefer not to say”). Age is stored as an approximate birth year; this is not age verification. Myanmar remains default, English fallback; new Myanmar copy is provisional.

`POST /api/training/intake` validates and saves profile, baseline measurement and schedule in one owner-scoped transaction. Identity comes from the session. Migration `20261117000000_training_intake` adds `intakeVersion`, `trainingLocation`, `healthClearance`. Existing accounts complete the new intake before receiving a personalized plan; history remains. The reviewed intake is available again from Profile. Clearing required body fields invalidates the intake. Updating intake preserves an existing programme week, resets its starting calibration and removes stale plan baselines/swaps rather than applying old decisions silently.

- Experience, activity, age/reported restrictions and subsequent feedback set the starting workload. Goal affects the strength/cardio distribution, target reps and recovery. Focus preferences prioritize suitable muscles; no spot-fat-loss or predicted-body-shape claims.
- Height/weight provide the body baseline and BMI reference; higher-impact options can be omitted. BMI is not a diagnosis or strength test. Sex is used by the existing energy-estimation model, never as a strength multiplier. Weight selection starts uncalibrated; the app does not infer a lifting weight from sex or body weight.
- Heart/chest-pain/dizziness/pregnancy flags require self-reported professional clearance before starting. Joint/back pain requires a protected area. These are conservative product gates, not medical clearance supplied by the app.

## Collections and player

`src/shared/exercise-place.ts` is the shared collection policy. **Home: exactly 19 supplied clips**, no equipment, no illustration fallback. **Gym: equipment-based exercises with available MP4 demos**, including machines, cables and free weights/bench; browser verification found 32 eligible videos. Unknown bodyweight illustrations do not become Home exercises. Historical database records remain for existing references; they are not new-plan candidates. Every new plan/quick-workout candidate needs a collection video. The compatibility Follow Along API uses the supplied arm-circle clip for gentle non-work preparation; banner workouts use the unified plan/player pipeline.

Bird dog uses the original clip for two separately logged sides. The opposite-side display is a labelled mirror cue, not a newly recorded video. Thus there are 19 files and 20 movement/side presentations; both sides are included in duration and completion.

“Workouts for you” opens an introduction with the actual server-generated exercise list, doses, rests and expandable videos. A 64 px red Start button creates the session only when pressed. Templates without matching supplied content (stretch/HIIT marketing banners) were removed. Gym users receive equipment workouts, including on a new browser with no local place preference.

Player: large video, large timer, Next; compact pause/exit/voice/fullscreen controls. Home runs timed circuits, Gym straight sets with elapsed time and optional reps/weight editing by tapping the target. Rest displays the next actual clip/side and starts automatically when its timer ends. Pause, hidden tabs and the quit sheet stop timers; Next on a partially completed timed block logs elapsed seconds, not the full target. A failed skip is not applied locally as if saved. Completion and progression still use owner-isolated records and post-session form/difficulty/pain feedback.

Duration counts 10 seconds preparation, all work blocks/both sides and all rests except after the last block. Gym rep duration is an estimate, marked with `~` in quick introductions; no phantom three-minute allowance is added. Available time is a ceiling: initial novice work is capped at 25 minutes, conservative/recovery starts at 20, with 3–4 sets rather than seven rounds just to fill time. UI explains shorter starts. Weekly reviews retain the existing bounded progression/recovery rules.

Rest values are transparent product heuristics: light Home blocks can use 10 seconds; beginning/inactive/higher-impact/older or reported-health contexts add recovery. Gym isolation starts at 90 seconds, major compounds 120; a strength goal uses 150/180 respectively, with extra recovery where appropriate. These exact app defaults are not presented as clinically optimized intervals.

- **PASS:** remote TypeScript, production build, 80 tests/21 files and EN/MY locale contracts. Tests cover atomic validation, owner isolation, missing baseline, Home's 19 IDs, strict Gym separation, persisted Gym default, age/activity/rest differences and exact bilateral timing.
- **PASS:** disposable browser signup → single-question intake/review with scroll pickers and separate current/desired body illustrations → collections → workout introduction → red Start → player; no production test users. Real preparation measured 10,118 ms, rest 10,208 ms, mirrored next-side video playing during rest, three short test blocks persisted exactly 2 seconds each.
- **PASS:** 36 picker layout cases: age/height/weight, EN/MY, light/dark, 320/390/1280 px; no horizontal overflow or page errors, no numeric text inputs, one slider per question and 60 px confirmation buttons. Native touch pan changed weight from 70 to 72 kg; keyboard Home/End reached 30/250 kg without exceeding bounds. Screenshots reviewed. Finite entry animations are allowed to finish before visual evidence; fixed footer overlap found during review was corrected.
- Full build/browser evidence: workspace `evidence/intake-release/`; sanitized handover: product `evidence/intake-release/`. Runtime tests use a separate Modal sandbox and temporary SQLite, without the customer Volume or gateway credentials. No paid LLM/TTS calls.
- **NOT TESTED:** physical phones, fluent Myanmar translation/voice certification, clinical effectiveness or coach approval of every recorded movement. Timer/feedback logs are user activity reports, not motion-sensor proof of exercise technique.

[ACSM's 2026 guidance](https://acsm.org/resistance-training-guidelines-update-2026/) supports regular resistance training tailored to ability and goals, with consistency taking priority over unnecessary complexity. [The primary position stand](https://pmc.ncbi.nlm.nih.gov/articles/PMC12965823/) reviews resistance-training variables and the limits of evidence. [CDC older-adult guidance](https://www.cdc.gov/physical-activity-basics/adding-older-adults/index.html) supports gradual starts and lower-volume returns after a break. The application's bounded rules are an engineering implementation informed by those sources, not a validated medical prescription.
